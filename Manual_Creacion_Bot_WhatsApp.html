1. Introducción y Arquitectura General

El presente documento recopila exhaustivamente la metodología técnica, diseño de arquitectura y código fuente implementado para construir el Bot Oficial de WhatsApp integrado al sistema de gestión de turnos médicos OscarSoft Turnos.

💡 ¿Por qué WhatsApp Cloud API Oficial de Meta y no librerías no oficiales? A diferencia de librerías basadas en emulación de navegador web (como Baileys, WPPConnect o Puppeteer), la API oficial en la nube de Meta garantiza:
  • Cero riesgo de baneo o bloqueo del número corporativo.
  • Alta disponibilidad garantizada con SLA oficial de Meta.
  • Entrega inmediata de webhooks mediante protocolo HTTP POST seguro.
  • Soporte de botones interactivos, listas, plantillas de marketing y comprobantes verificados.

3. Base de Datos: Cero Hardcodeo y Emojis

Una de las reglas arquitectónicas más importantes del sistema es que ningún mensaje fijo ni flujo conversacional debe quedar cableado en el código JavaScript. Toda respuesta proviene de la tabla bot_respuestas.

✅ Soporte Mandatorio de Emojis: utf8mb4 Los mensajes de WhatsApp utilizan activamente emoticones (🏥, 🗓️, ⏰, 👨‍⚕️, ❌, ✅). En MySQL, el juego de caracteres estándar utf8 solo soporta hasta 3 bytes, lo que causa un error fatal al intentar guardar un emoji. Tanto la base de datos como las tablas y la conexión de Node.js deben crearse en utf8mb4 con intercalación utf8mb4_unicode_ci.

Estructura DDL de la Tabla bot_respuestas

CREATE TABLE IF NOT EXISTS bot_respuestas (
  id INT AUTO_INCREMENT PRIMARY KEY,
  clave VARCHAR(80) NOT NULL UNIQUE,
  titulo VARCHAR(150) NOT NULL,
  descripcion VARCHAR(255) NULL,
  disparador VARCHAR(200) NULL,
  mensaje TEXT NOT NULL,
  activo TINYINT(1) DEFAULT 1,
  creado_en TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  actualizado_en TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

Mecanismo de Lectura y Fallback en JavaScript

async function getBotMessage(clave, fallback, variables = {}) {
  try {
    const [rows] = await pool.query(
      'SELECT mensaje FROM bot_respuestas WHERE clave = ? AND activo = 1 LIMIT 1',
      [clave]
    );
    let text = (rows.length > 0 && rows[0].mensaje) ? rows[0].mensaje : fallback;
    for (const [k, v] of Object.entries(variables)) {
      text = text.replaceAll(`{${k}}`, v || '');
    }
    return text;
  } catch (err) {
    let text = fallback;
    for (const [k, v] of Object.entries(variables)) {
      text = text.replaceAll(`{${k}}`, v || '');
    }
    return text;
  }
}

4. Implementación del Backend (Node.js & Express)

El backend gestiona dos responsabilidades esenciales: validar el webhook y recibir los mensajes entrantes.

1. Verificación del Webhook por Meta (Endpoint GET)

Cuando se configura el Webhook en el portal de Meta, sus servidores disparan una consulta GET con tres parámetros:

  • hub.mode: Debe tener el valor subscribe.
  • hub.verify_token: Debe coincidir exactamente con nuestro WHATSAPP_VERIFY_TOKEN.
  • hub.challenge: Un número aleatorio que nuestro servidor debe devolver con código HTTP 200.
router.get('/webhook', (req, res) => {
  const mode = req.query['hub.mode'];
  const token = req.query['hub.verify_token'];
  const challenge = req.query['hub.challenge'];
  const expectedToken = process.env.WHATSAPP_VERIFY_TOKEN;

  if (mode && token) {
    if (mode === 'subscribe' && token === expectedToken) {
      console.log('✅ Webhook verificado exitosamente por Meta');
      return res.status(200).send(challenge);
    }
    return res.sendStatus(403);
  }
  return res.sendStatus(400);
});

2. Recepción de Mensajes del Paciente (Endpoint POST)

⚡ Regla de Oro de Meta: Responder 200 OK Inmediatamente Meta exige que el endpoint POST responda con código HTTP 200 en menos de 3 segundos. Si el servidor demora consultando la base de datos antes de enviar la respuesta HTTP, Meta considera que hubo un fallo y reintenta enviar el mismo mensaje una y otra vez en bucle. Siempre debe ejecutarse res.status(200).send('EVENT_RECEIVED') antes o al inicio del procesamiento.

3. Normalización Telefónica para Argentina (Prefijo 9)

En Argentina existe una particularidad técnica con WhatsApp: los teléfonos móviles a veces son reportados por Meta con el prefijo 549... (13 dígitos) y a veces como 54... (12 dígitos). Para evitar que los mensajes fallen, se implementó un mecanismo de reintento dual:

async function sendWhatsAppMessage(toPhone, messageText) {
  const phoneNumberId = process.env.WHATSAPP_PHONE_NUMBER_ID;
  const token = process.env.WHATSAPP_ACCESS_TOKEN;

  let targetPhones = [toPhone];
  const digits = String(toPhone).replace(/\D/g, '');
  if (digits.startsWith('549') && digits.length === 13) {
    targetPhones = ['54' + digits.slice(3), toPhone];
  } else if (digits.startsWith('54') && digits.length === 12) {
    targetPhones = [digits, '549' + digits.slice(2)];
  }

  const url = `https://graph.facebook.com/v21.0/${phoneNumberId}/messages`;

  for (const phone of targetPhones) {
    const res = await fetch(url, {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${token}`,
        'Content-Type': 'application/json'
      },
      body: JSON.stringify({
        messaging_product: 'whatsapp',
        to: phone,
        type: 'text',
        text: { preview_url: false, body: messageText }
      })
    });
    if (res.ok) return true;
  }
  return false;
}

5. Máquina de Estados y Flujos Conversacionales

Cada usuario mantiene una sesión en memoria vinculada a su número telefónico (userSessions.get(phone)).

Estado (Step) Objetivo Siguiente Paso
INIT Menú de bienvenida o detección de FAQ por palabra clave. Según número elegido (1 a 5)
AWAIT_MEDICO_SEARCH El usuario escribe el nombre o apellido del médico. SELECT_MEDICO
SELECT_MEDICO Elige el médico de la lista coincidente (1, 2, ...). SELECT_FECHA

AWAIT_DNI Ingresa DNI del paciente para validar titularidad. SELECT_COBERTURA o Invitación

Flujo 1: Agendamiento y Validación de Paciente

Si el paciente ingresa un DNI que no existe en la base de datos de usuarios, el bot no se rompe ni cancela abruptamente; responde con la plantilla dni_no_registrado, ofreciéndole el link web oficial para completar sus datos personales y registrar su carnet de obra social:

Mensaje enviado por el bot:
"❌ DNI no registrado. No encontramos ninguna cuenta registrada con el DNI 32123456. Para poder agendar tu turno, primero registrate en: https://oscarsoft.com.ar/turnos/login?registro=1"

Flujo 2: Consulta y Cancelación en 2 Pasos

Para cancelar un turno agendado (Opción 5), el sistema exige:

  1. Ingreso del DNI para listar sus turnos activos futuros.
  2. Selección del turno específico mediante su número de lista.
  3. Confirmación previa de seguridad: El bot pregunta explícitamente:
    *1* - ✅ Sí, cancelar este turno / *2* - ❌ No, conservar mi turno.
    Solo si presiona 1 se ejecuta la sentencia SQL de liberación del turno y se notifica al paciente.

Disparadores de FAQ Inteligentes

La tabla bot_respuestas posee la columna disparador. Si un paciente escribe en cualquier momento palabras como "sedes", "donde atienden", "requisitos" o "carnet", el bot salta directamente a la respuesta adecuada sin necesidad de navegar el menú numérico.

router.get('/bot-respuestas', authMiddleware, requireAdmin, async (req, res) => {
  const [rows] = await pool.query('SELECT * FROM bot_respuestas ORDER BY id ASC');

// Actualizar una respuesta existente
router.put('/bot-respuestas/:id', authMiddleware, requireAdmin, async (req, res) => {
  const { id } = req.params;
  const { titulo, descripcion, disparador, mensaje, activo } = req.body;
  await pool.query(
    'UPDATE bot_respuestas SET titulo = ?, descripcion = ?, disparador = ?, mensaje = ?, activo = ? WHERE id = ?',
    [titulo, descripcion, disparador, mensaje, activo ? 1 : 0, id]
  );
  res.json({ status: 'ok', message: 'Respuesta actualizada exitosamente.' });
});

7. Guía de Despliegue, Testing y Buenas Prácticas

Testing en Entorno Local (Desarrollo)

Como los servidores de Meta necesitan enviar peticiones HTTP a una dirección accesible desde internet con certificado SSL (HTTPS), no se puede ingresar http://localhost:5060 directamente en Meta.

1
Levantar un Túnel HTTPS Seguro

Se puede utilizar Cloudflare Tunnels o Ngrok:

ngrok http 5060

Ngrok otorgará una URL temporal pública (ej: https://abcd-123.ngrok-free.app).

2
Configurar la URL en Meta

Pegar la URL generada: https://abcd-123.ngrok-free.app/api/turnos/whatsapp/webhook y verificar con el token.

3
Enviar Mensaje de Prueba desde un Teléfono Autorizado

En modo Desarrollo de Meta, solo los números registrados en la lista de Destinatarios de Prueba (To Phones) pueden enviar y recibir mensajes.

Despliegue en Producción

Checklist de Salida a Producción:

  1. Nginx Reverse Proxy: Configurar Nginx para redirigir el tráfico del subdominio o ruta /api/turnos/whatsapp hacia el puerto de Node.js (5060).
  2. Certificado SSL/TLS Válido: Meta rechaza de inmediato cualquier webhook con certificado autofirmado o vencido. Usar Certbot (Let's Encrypt).
  3. Gestor de Procesos PM2: Ejecutar la aplicación con pm2 start server/index.js --name "turnos-backend" con reinicio automático.
  4. Verificación de Negocio en Meta: Para enviar mensajes a cualquier paciente sin restricción de prueba, se debe completar la Verificación de Empresa (Business Verification) en el Administrador Comercial de Meta.

Errores Frecuentes y Cómo Solucionarlos

Error / Síntoma Causa Raíz Solución Definitiva
Verification failed (403) El verify_token ingresado en Meta no coincide con el .env. Verificar mayúsculas y espacios en WHATSAPP_VERIFY_TOKEN.
Error 190 (Invalid OAuth) El token de acceso de 24 horas expiró. Crear System User permanente en Business Manager y renovar WHATSAPP_ACCESS_TOKEN.
Incorrect string value (emojis) La tabla de MySQL está en latin1 o utf8 (3 bytes). Ejecutar ALTER TABLE bot_respuestas CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
Bucle infinito de mensajes de Meta El endpoint POST tardó más de 3 segundos en responder. Enviar res.status(200).send('EVENT_RECEIVED') al inicio de la función.
